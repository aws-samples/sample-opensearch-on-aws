# Step 4: OpenSearch UI application, workspace and datasets

`04_ui.py` creates the application, enables Ask AI, and creates the workspace with the collection attached. You
create the datasets in the UI (the UI builds each dataset's field list from the live index; a script cannot).

## Application and workspace

```
python deploy/04_ui.py --name agentobs --region us-east-1 --admins arn:aws:sts::<account-id>:assumed-role/<RoleName>/<SessionName>
```

It waits until the application is ACTIVE, enables the Ask AI / Agentic Chat features (free; off by default on a new
application), creates an Observability workspace named `Astronomy Shop` (change with `--workspace`), and prints
`UI_ENDPOINT`. For `--admins`, use the identity exactly as it appears when signed in: for an IAM user its user ARN
(`arn:aws:iam::<account-id>:user/<name>`); for a federated or assumed role the **session ARN**
(`arn:aws:sts::<account-id>:assumed-role/<RoleName>/<SessionName>`, as shown by `aws sts get-caller-identity`),
not the role ARN. The workspace is granted write access to `--admins`, so the same identity can edit it. That
identity must also be in the collection's data access policy (step 1, `--principals`), where the IAM **role** ARN
(`arn:aws:iam::<account-id>:role/<RoleName>`) or user ARN is used.

Open `UI_ENDPOINT` in a browser while signed in to the AWS console as that identity, and pick the **Astronomy Shop**
workspace from the workspace list.

## Datasets (index patterns)

Let's browse the data. In the workspace, open **Data → Datasets → Create dataset**, choose the collection as the
data source, and create one dataset per pattern below:

| Dataset name | Pattern | Time field |
|---|---|---|
| Astronomy Shop Traces | `otel-v1-apm-span-*` | `startTime` |
| Astronomy Shop Logs | `otel-logs-*` | `@timestamp` |
| Agent Evaluations (after step 5) | `agent-evals` | `@timestamp` |

Choose the time field carefully: it is the field OpenSearch UI uses to plot each dataset as a live time stream in
Discover and the dashboards, so it must be the index's real timestamp (the ones above). The UI builds the field
list when you create the dataset; if new fields appear later (such as the lifted `gen_ai.*` keys), refresh it with
Datasets → pattern → refresh icon.

## Check that data is arriving

In **Discover** with the traces dataset, time range last 15 minutes, run (PPL):
```
source = otel-v1-apm-span-* | stats count() by serviceName | sort - `count()`
```
About twenty services should appear within 5 minutes of the OpenTelemetry Demo starting. Then **Observability → Agent monitoring →
Traces**: one row per assistant conversation, with its token count. Open a row and select an LLM span (`ChatLLM.chat`) to see which model answered (`gen_ai.response.model`). Nothing needs to be enabled for the Agent
Traces page; it reads the `gen_ai.*` fields the pipeline lifts.

Now build the dashboards from `../dashboards/dashboard-1-health.md` and `dashboard-2-ai-cost.md`.
