# Step 3 (part 1): OpenSearch UI application, workspace and datasets

The application is created by `04_ui.py`; the workspace and datasets are console steps.

## Application

```bash
python deploy/04_ui.py --name agentobs --region us-east-1 \
    --admins arn:aws:sts::<account-id>:assumed-role/<RoleName>/<SessionName>
```

It waits until the application is ACTIVE and prints `UI_ENDPOINT`. For `--admins`, use the identity exactly as it
appears when signed in: for an IAM user its user ARN
(`arn:aws:iam::<account-id>:user/<name>`); for a federated or assumed role the **session ARN**
(`arn:aws:sts::<account-id>:assumed-role/<RoleName>/<SessionName>`, as shown by `aws sts get-caller-identity`),
not the role ARN. The same person must also be in the collection's data access policy (step 1, `--principals`), where
the IAM **role** ARN (`arn:aws:iam::<account-id>:role/<RoleName>`) or user ARN is used. Open the endpoint in a
browser while signed in to the AWS console as that identity.

## Workspace

1. In OpenSearch UI choose **Create workspace**, type *Observability*, name it (for example `Astronomy Shop
   Operations`), and associate the collection data source.
2. Add collaborators as needed (read-only for viewers).

## Datasets (index patterns)

In the workspace, **Data → Datasets → Create**:

| Dataset name | Pattern | Time field |
|---|---|---|
| Astronomy Shop Traces | `otel-v1-apm-span-*` | `startTime` |
| Astronomy Shop Logs | `otel-logs-*` | `time` |
| Agent Evaluations (after step 4) | `agent-evals` | `@timestamp` |

After the first data arrives, refresh each dataset's field list (Datasets → pattern → refresh icon) so new fields,
including the lifted `gen_ai.*` keys, appear.

## Check that data is arriving

In **Discover** with the traces dataset, time range last 15 minutes, run (PPL):
```
source = otel-v1-apm-span-* | stats count() by serviceName | sort - `count()`
```
About twenty services should appear within 5 minutes of the OpenTelemetry Demo starting. Then **Observability → Agent monitoring →
Traces**: one row per assistant conversation, with its token count. Open a row and select an LLM span (`ChatLLM.chat`) to see which model answered (`gen_ai.response.model`). Nothing needs to be enabled for the Agent
Traces page; it reads the `gen_ai.*` fields the pipeline lifts.

Now build the dashboards from `../dashboards/dashboard-1-health.md` and `dashboard-2-ai-cost.md`.
